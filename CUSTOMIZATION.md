# Branding and presentation

`profiles/default.json` supplies deploy-time public settings. `STORE_CONFIG_PATH` can select a different profile. The Super Admin can edit branding, contact information, policies, bank instructions, colours and feature flags in **Settings**; overrides persist in that store's database. Profile edits do not overwrite existing database settings. Store identity is fixed by deployment.

Use `layout: "editorial"` for serif typography, muted light surfaces and an open collection layout. Use `layout: "electronics"` for sans-serif headlines, dark surfaces, gold accents and framed product cards. SK Plug is an example of the latter, not a hardcoded backend mode. Colours are six-digit hex values. Logo/favicon must be local `/static/` asset paths. Logo text remains visible and accessible alongside an optional image. Replace demo SVGs with approved client artwork when adapting the hero; current demo artwork is deliberately labelled as an illustration.

Presentation is in `static/app.js` (`shell`, `home`, `card`, `grid`, `detail`, cart/checkout/admin renderers) and `static/style.css` (base tokens plus layout overrides). You can replace these renderers or build a completely different frontend against the same `/api/` endpoints. Preserve the server's integer-kobo pricing, exact variant IDs, checkout idempotency key, CSRF header and role checks. Never decide paid status in the browser. Browser cart storage is namespaced by store ID; do not rename it to a shared global key.

Features: `whatsappCheckout`, `bankTransfer`, `onlinePayment`, `instalments`, `delivery`, `pickup`. Enabling a flag is not a substitute for configuring a payment destination or negotiating a business agreement. With no configured method checkout fails safely. Disabling instalment marketing does not erase or forbid legitimate partial receipt records; the owner ledger still records actual money received. Currency is currently NGN only.

Category hierarchy is editable under Categories. Product filters currently use exact categories, so selecting a parent does not automatically include all descendants. Specifications are text label/value pairs. Product photos are uploaded as safe raster files, optimized by the server; arbitrary SVG uploads are not supported. The shipped static SVG demonstrations are trusted source assets.

The component API is intentionally lightweight vanilla JavaScript rather than a new framework. It remains one frontend entrypoint; as designs grow, extract these component functions into native ES modules or a chosen frontend without rewriting commerce. Forms report invalid requests through the accessible notification region; semantic labels, focus outlines, image descriptions and reduced-motion support are included. This is not a certified accessibility audit.
